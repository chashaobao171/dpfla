## 一句话

**DPFLA**：联邦学习投毒防御项目，落地场景 **VisDrone + YOLOv8** 目标检测。
核心目标：**无攻击联邦基线 mAP@0.5 ≥ 32%**（现基线约 22–24%，集中式 oracle 约 41%）。

  - **FedAvgM（服务端动量）与梯度裁剪已改为环境变量门控、默认关闭**（`FL_SERVER_MOMENTUM=0`、`FL_GRAD_CLIP=0`）。

## 当前阻塞 / 未决

1. **mAP 距目标差 ~8–10 个点，根因未定位**。已知**不是**聚合算法的问题（见 `04_Retracted.md`）。
2. 需要**有卡环境**才能继续实验。
3. "换聚合模型"这条路已被证明是错误方向，已回退。真正可动的是**训练配方（LR / 轮数 / Mosaic / 模型容量）**。

## 下一步（建议，全部需有卡）

1. 先复现基线：R1≈3.3%、R6≈22% 对齐历史，确认链路无回归。
2. 做**单变量**对照，一次只改一个：

   | 变量 | 从 → 到 | 备注 |
   |------|--------|------|
   | 通信轮数 | 50 → 100+ | 基线 R26-33 才到 23.7%，说明轮数不足 |
   | Mosaic | 0.5 → 1.0 | FedAIoT 配置，待验证 |

   | 模型 | s → m / l | 集中式 oracle 用 l，容量可能是瓶颈 |
   | 防御聚合 | FedAvg vs DPFLA / FedLA | **本项目本体对比**，不是 FedAvgM |

3. 禁止一次性改多个变量后归因（历史教训见 `03_History.md` / `04_Retracted.md`）。
